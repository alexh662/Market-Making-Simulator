# Decisions

## 2026-08-11 Arithmetic vs geometric Brownian motion
**Decision:** Mid-price follows arithmetic Brownian motion with no drift, `S_{t+dt} = S_t + sigma * sqrt(dt) * Z`.
**Alternatives considered:** Geometric Brownian motion (log-normal price, proportional volatility).
**Reasoning:** CLAUDE.md section 2.2 mandates arithmetic BM as the Avellaneda-Stoikov convention; the closed-form quoting solution (reservation price, optimal spread) is derived under arithmetic BM and does not carry over cleanly to GBM. Arithmetic dynamics also keep inventory PnL linear in price increments, which is what the PnL decomposition in section 5 relies on.
**Consequence:** Prices can in principle go negative over long horizons or high sigma, but at the frozen defaults (S0=100, sigma=2.0, T=1.0) this is not a practical concern. No drift is added in the base case so PnL variance can be attributed to inventory risk rather than a directional bet; drift is reserved as an optional robustness check (section 6.7).

## 2026-08-11 Config validation rules
**Decision:** Config is represented as frozen dataclasses (`PriceConfig`, `FlowConfig`, `StrategyConfig`, `SimulationConfig`, `Config`) that validate their own fields in `__post_init__`, raising `ValueError` on: `sigma <= 0`, `dt <= 0`, `T <= 0`, `kappa <= 0`, `gamma <= 0`, `tick_size <= 0`, `n_paths < 1`, `phi_informed` outside `[0, 1]`, and `T / dt` not within `1e-9` of an integer.
**Alternatives considered:** A single flat config dataclass; validating with a schema library (e.g. `pydantic`); validating only at the point of use rather than at construction.
**Reasoning:** CLAUDE.md section 13 requires frozen dataclasses for config (no dictionaries passed as configuration) and forbids adding dependencies without logging them here — `pydantic` was not added for that reason. Validating in `__post_init__` means an invalid config fails immediately at construction, whether built from YAML or directly in tests, rather than surfacing as a confusing downstream numerical error (e.g. a `dt` that doesn't evenly divide `T` would silently produce a path one element short or long). The `T / dt` integer check uses a `1e-9` tolerance because floating-point division (e.g. `1.0 / 0.005`) is not exact.
**Consequence:** Each config section validates independently of the others, which is sufficient since none of the required rules are cross-section. If a future rule needs to compare fields across sections (e.g. price vs strategy), it will need to move into `Config.__post_init__` instead.

## 2026-08-11 Simulator internals accept raw parameters, not a validated Config
**Decision:** `run_episode` in `src/simulator.py` takes individual keyword parameters (`sigma`, `A`, `phi_informed`, etc.) rather than a `Config` object, and performs no validation of its own.
**Alternatives considered:** Passing a `Config` object straight through to `run_episode`; relaxing `PriceConfig`'s `sigma > 0` check to allow the section 8 sanity check.
**Reasoning:** CLAUDE.md section 8's mandatory sanity checks require running the simulator with `sigma = 0` and `A = 0`, but section 12's calibration note and the earlier config milestone both require `PriceConfig` to reject `sigma <= 0` for real experiment configs. Routing every call through the validated `Config` would make the two requirements mutually exclusive. `Config`/`load_config` remains the strict boundary for anything loaded from YAML (section 13's "no dictionaries passed as configuration" applies there); `run_episode` is an internal function, trusted per the project's style guide ("only validate at system boundaries"), so it accepts whatever the caller passes, including the degenerate test parameterisations.
**Consequence:** Callers driving `run_episode` from a real `Config` (e.g. `experiments.py`, not yet written) must unpack its fields explicitly rather than passing the object. `sigma = 0` and `A = 0` are valid simulator inputs for tests even though `config/base.yaml` could never validate to those values.

## 2026-08-11 Informed-flow mechanism
**Decision:** Each step, ordinary per-side fill draws happen exactly as in section 2.6 (independent Bernoulli per side from the Poisson intensity), unconditioned on informed status. Any arrival that does fill is then reclassified informed with probability `phi_informed`. An informed bid fill (someone selling into us) only executes if the mid is about to fall over the next `informed_horizon` steps; an informed ask fill only executes if the mid is about to rise. An informed arrival on the wrong side is cancelled outright rather than flipped to the other side.
**Alternatives considered:** Overriding the side of an informed arrival to force it onto the profitable side regardless of the independent per-side draw; adding a separate, additive informed-arrival process on top of the uninformed one.
**Reasoning:** CLAUDE.md section 2.7 says the informed order's "direction is chosen to be correct," but section 2.6 already fixes fill mechanics as two independent per-side draws, and overriding the side after the fact would silently violate the stated distance-decay fill probabilities. Gating (cancel-if-wrong) preserves the section 2.6 mechanics exactly, keeps `phi_informed` as a clean fraction of raw arrivals, and yields the intended effect: as `phi_informed` rises, more of our fills are will-be-informed and a smaller fraction of those informed attempts survive being on the wrong side, so filled flow is pushed toward the mid's true direction. This directly produces the negative adverse-selection cost the decomposition in section 5.2 measures.
**Consequence:** Realised fill counts fall somewhat as `phi_informed` rises (informed-but-wrong arrivals vanish rather than converting to a same-side uninformed fill), which is a deliberate and documented side effect, not a bug — it must be accounted for when reading the fill-count column in the informed-flow sweep (section 6.6).

## 2026-08-11 FillRecord horizon field uses adverse_selection_horizon, not informed_horizon
**Decision:** `FillRecord.mid_after_horizon` is the mid price `adverse_selection_horizon` steps after the fill, not `informed_horizon` steps after. The `informed_horizon`-ahead price used to classify a fill as informed (section 2.7) is consumed internally by the simulator and only surfaces via `was_informed`; it is not stored as its own column.
**Alternatives considered:** Storing both horizons as separate columns; storing only the `informed_horizon` price since that is what section 2.7 names first.
**Reasoning:** Section 4.3 requires everything downstream (section 5.2's adverse-selection decomposition) to read from the recorded frames without re-running the simulation, and section 5.2's formula explicitly uses `h = adverse_selection_horizon`. Both horizons default to 20 in `config/base.yaml`, which makes the two choices numerically identical today, but they are conceptually distinct knobs (one governs the counterparty model, the other governs how PnL is attributed) and only one of them is what `decomposition.py` will need.
**Consequence:** If `informed_horizon` and `adverse_selection_horizon` are ever set to different values, `mid_after_horizon` still reflects the attribution horizon, and `was_informed` reflects the (unrecorded) classification horizon — the two can diverge, which is intentional.

## 2026-08-11 StateRecord bid/ask/spread are post-rounding; reservation_price is pre-rounding
**Decision:** In `StateRecord`, `bid`/`ask`/`spread_total` are the tick-rounded, actually-tradeable quotes. `reservation_price` is `(raw_bid + raw_ask) / 2` computed from the strategy's raw output before tick rounding.
**Alternatives considered:** Recording everything post-rounding; recording everything pre-rounding; extending the `Strategy.quote()` interface to return a reservation price explicitly.
**Reasoning:** The `Strategy` protocol in section 6.1 returns only `tuple[float, float]`, and CLAUDE.md is the source of truth for that interface, so it was not extended. Section 2.5 states quotes are placed symmetrically about the reservation price, which means `(bid + ask) / 2` recovers it exactly for any conforming strategy, without needing a dedicated field. Post-rounding is used for `bid`/`ask`/`spread_total` because those are what a counterparty actually trades against and what section 4.2 means by "average quoted spread" for the liquidation cost; pre-rounding is used for `reservation_price` because that is the model quantity (`r_t` in section 2.3), not a market-facing price.
**Consequence:** `spread_total` in the state frame is the realised, tick-rounded spread, which can be very slightly wider than `2 * |reservation_price - mid|` implies before rounding; this gap is the rounding-collision counter's effect and is expected, not an error.

## 2026-08-12 Total spread is not monotonic in gamma in general
**Decision:** `test_total_spread_increases_in_gamma_at_frozen_default_parameters` checks monotonicity only across the section 6.3 gamma sweep `[0.01, 0.05, 0.1, 0.2, 0.5, 1.0, 2.0, 5.0]`, at `t=0` (`T-t=T=1.0`), with the frozen default `sigma=2.0`, `kappa=1.5`. The Avellaneda-Stoikov formula itself was not changed to force monotonicity.
**Alternatives considered:** Asserting monotonicity in gamma unconditionally (fails); clipping or otherwise modifying the spread formula so it is monotonic everywhere (would depart from the closed-form solution in section 2.4, which is not permitted).
**Reasoning:** `spread_total(gamma) = gamma*sigma^2*(T-t) + (2/gamma)*ln(1+gamma/kappa)` has two terms with opposite gamma-dependence: the inventory term is linear-increasing in gamma, the microstructure term `(2/gamma)*ln(1+gamma/kappa)` is decreasing in gamma for large enough gamma. At the frozen defaults with `T-t=1.0`, the inventory term's increase dominates across the whole sweep (spread rises from 1.369 at gamma=0.01 to 20.587 at gamma=5.0, monotonically). But near the episode horizon this breaks down: at `T-t=0.1`, spread at gamma=0.01 is 1.333 and at gamma=0.05 is 1.332 — a decrease. The counter-example was found by hand calculation, not by search, so it is a real, reproducible property of the formula, not a numerical artefact.
**Consequence:** Any future code (e.g. `experiments.py`'s gamma sweep, section 6.3) that assumes total spread is monotonic in gamma must restrict that assumption to conditions similar to the frozen defaults at `t` near 0. Reporting the gamma sweep's Sharpe peak (section 6.3) should not conflate "total spread is smallest at low gamma" with a universal property.

## 2026-08-12 Mid-crossing counted, not clipped
**Decision:** `EpisodeResult.mid_crossing_count` counts every step where the strategy's raw (pre-tick-rounding) bid is above the mid or raw ask is below the mid. The simulator does not clip, clamp, or otherwise prevent this; it only counts it.
**Alternatives considered:** Clamping the quote to never cross the mid; silently ignoring the condition (the default absent this change); raising an exception.
**Reasoning:** At large `|q|`, the reservation-price shift `q*gamma*sigma^2*(T-t)` can exceed half the total spread, pushing both quotes to the same side of the true mid — e.g. at defaults, `q=3` and `t=0` is already enough (shift 1.2 vs half-spread 0.845). This is a real, reproducible artefact of the closed-form AS solution at extreme inventory, not a bug, and altering the formula to prevent it would depart from CLAUDE.md section 2.4. Since it is common enough at default parameters (observed on several of the first ten Monte Carlo paths), it needs to be visible rather than silently baked into fill behaviour.
**Consequence:** A mid-crossed quote is still tradeable exactly as any other quote (the fill-probability formula in section 2.6 does not special-case it): a crossed ask, being below the true mid, gets a very high fill probability, which mechanically pulls inventory back toward zero. This is a real, useful self-correcting property of the model worth noting in the M5/M6 write-up, not something to engineer away.

**Decision:** Default `gamma` changed from `0.1` to `0.01`.
**Alternatives considered:** Keeping `0.1`, or going below `0.001`.

## 2026-08-12 mid crossing is non monotonic in gamma
**Decision:** No code change; recording an empirical finding for later use.
**Alternatives considered:** N/A — this is an observation, not a design choice.
**Reasoning:** Mid crossings per episode are near zero for `gamma` at or below `0.01`, peak at roughly `19.6` per episode at `gamma=0.5`, then fall at `gamma=5.0` because fill counts collapse to about `12` per episode, leaving few opportunities to cross. The peak is not at the extreme of the parameter range in either direction — it is driven by two competing effects (skew magnitude rising with gamma, fill count falling with gamma) that trade off in the middle.
**Consequence:** Candidate finding for the README: mid-crossing frequency is a distinct, non-monotonic diagnostic from inventory variance or PnL, worth its own sentence in the write-up rather than being folded into the gamma sweep narrative.

## 2026-08-12 adverse selection horizon clamps at the path end
**Decision:** For a fill occurring within `h = adverse_selection_horizon` steps of the end of the path, the forward mid used in the section 5.2 adverse-selection sum is clamped to the **final mid** (`path[n_steps]`) rather than the fill being excluded from the sum. Implemented in `run_episode` as `h_as = min(adverse_selection_horizon, n_steps - i)`, so `FillRecord.mid_after_horizon` already carries the clamped value; `src/decomposition.py` consumes it as-is. The count of clamped fills per episode is recomputed from recorded fill times by `count_clamped_fills` and reported as `Decomposition.clamped_fill_count`.
**Alternatives considered:** Excluding late fills from the adverse-selection sum entirely; extending the simulated path beyond `T` purely to supply forward mids; leaving `mid_after_horizon` undefined (NaN) for late fills.
**Reasoning:** Excluding late fills would silently change the denominator of the attribution — spread capture would still count those fills while adverse selection would not, so the section 5.1/5.2 identity `(B) = adverse_selection + residual` would no longer partition the same set of trades, and the residual would absorb a systematically biased remainder. Clamping keeps every fill in both terms. It biases each clamped fill's measured adverse selection toward zero (a shorter effective horizon means a smaller price move), which is a known, bounded, and reported distortion rather than a hidden one. Extending the path past `T` was rejected because `T` is the episode horizon in the AS closed form (section 2.3-2.4) and inventing post-`T` prices would contaminate the terminal handling in section 4.2.
**Consequence:** At the frozen defaults (200 steps, `h=20`) roughly the last 10% of each episode's fills are clamped — measured means are 9.66 per episode for `SymmetricFixedSpread` and 7.83 for `AvellanedaStoikov`, against mean fill counts of 103.31 and 82.58, i.e. about 9.4%. Reported alongside every breakdown so the magnitude of the distortion is always visible. If `adverse_selection_horizon` is ever raised substantially relative to `T/dt`, this fraction grows and the attribution weakens accordingly.

## 2026-08-12 no endogenous adverse selection at phi_informed = 0
**Decision:** Recording an empirical and analytical finding, and departing from one specified test assertion because of it. `tests/test_decomposition.py::test_adverse_selection_without_informed_flow_is_indistinguishable_from_zero` asserts that mean adverse selection at `phi_informed = 0` is **statistically indistinguishable from zero** (`|t| < 3`), not that it is strictly negative. No sign was adjusted and no tolerance was changed.
**Alternatives considered:** Asserting strictly negative as originally specified; asserting exactly zero; omitting the test.
**Reasoning:** The specified assertion is not true of this simulator, and would have passed only by accident of the frozen base seed. With `phi_informed = 0` the fill indicator at step `i` is a function of the price path up to `i` and of the independent uniform draws at `i`, while the forward move `mid_{t+h} - mid_t` is a sum of strictly later, independent increments of a **driftless** arithmetic walk. The two are independent, so `E[signed_size · forward_move] = E[signed_size] · 0 = 0` exactly. Measured directly, pooled over ~400 episodes: mean forward mid move after a buy fill `+0.0022` (SE `0.0041`), after a sell fill `-0.0027` (SE `0.0041`) — both zero. Across eight different base seeds the 500-path mean came out **positive in 4/8** runs for `SymmetricFixedSpread` and **5/8** for `AvellanedaStoikov`, with `|t|` ranging `0.03` to `2.08`; at the frozen seed it is `-0.02` (`t=-0.09`) and `-0.10` (`t=-0.49`). The sign is pure sampling noise. Asserting "strictly negative" would have encoded a seed-dependent accident as a correctness requirement.
**Reasoning (mechanism):** The deeper cause is that this simulator has **zero quote latency**: quotes are recentred on the current mid at every step, so there is no stale quote to be picked off. Real endogenous adverse selection comes from a resting order being executed at a price the market has already moved away from. CLAUDE.md section 2.7's premise that "the pure AS model generates some adverse selection endogenously" therefore does not hold in this implementation — here adverse selection is generated **entirely** by the explicit informed-flow mechanism. This is recorded as a disagreement with the file per section 0 rather than silently worked around.
**Consequence:** All measured adverse selection in this project is attributable to `phi_informed`, which strengthens the section 6.6 sweep (the crossover is a clean function of one parameter) but must be stated plainly in the README walk-backs: the simulator does not model queue position or quote latency, so it cannot produce pick-off adverse selection, and section 6.7's queue-position/requoting-cost robustness check is the natural place to introduce it. The `phi_informed = 0.0` versus `0.4` comparison remains a strong, robust test (means `-0.02` vs `-10.90` for fixed spread, `-0.10` vs `-8.13` for AS) and is retained.

## 2026-08-12 no endogenous adverse selection without quote latency
**Decision:** CLAUDE.md section 2.7 updated to state that this simulator generates no adverse selection endogenously, replacing the prior (incorrect) claim that "the pure AS model generates some adverse selection endogenously." This entry is the analytical and empirical record behind that edit. **README walk-back candidate:** state this plainly in the limitations section rather than letting it surface only as a quiet test-assertion choice.
**Alternatives considered:** Leaving CLAUDE.md's original claim in place and treating the `phi_informed = 0` measurement as a fluke of the frozen seed (rejected — the eight-seed sweep below shows it is not); adding quote latency now to make the endogenous claim true (rejected — out of scope for M4, and section 6.7 is the designated place for it).
**Analytical argument:** With `phi_informed = 0`, the fill indicator for a quote at step `i` is a function only of the price path up to `i` and of independent uniform draws at `i`. The forward move `mid_{t+h} - mid_t` used in the section 5.2 adverse-selection sum is a sum of strictly later, independent increments of a **driftless** arithmetic Brownian walk (section 2.2). Because the two are independent, `E[signed_size · forward_move] = E[signed_size] · E[forward_move] = E[signed_size] · 0 = 0` exactly, for any strategy that determines its quote from `(t, S_t, q_t)` alone.
**Empirical figures:** Pooled over ~400 episodes at `phi_informed = 0` (frozen defaults, `SymmetricFixedSpread`): mean forward mid move after a buy fill `+0.0022` (SE `0.0041`, n≈22346), after a sell fill `-0.0027` (SE `0.0041`, n≈22340) — both statistically zero. Across eight different base seeds, the 500-path mean adverse selection came out **positive in 4 of 8** runs for `SymmetricFixedSpread` and **5 of 8** for `AvellanedaStoikov`, with `|t|` ranging from `0.03` to `2.08`; at the project's frozen base seed (`20260811`) it happens to read `-0.02` (`t=-0.09`) for the fixed-spread baseline and `-0.10` (`t=-0.49`) for AS. The sign is sampling noise, not a directional effect.
**Mechanism:** Every strategy in this project recomputes its quote from scratch every step and posts it immediately — there is no persistence, no queue, and no delay between a quote becoming stale and it being replaced. Adverse selection in real markets arises from a **resting** quote being executed after the market has already moved past it; with zero quote latency there is no such window, so nothing here can generate that effect. All measured adverse selection is therefore attributable entirely to the explicit `phi_informed` informed-flow mechanism (section 2.7), which looks ahead by construction.
**Consequence:** Adding quote latency — letting a posted quote persist for more than one step before it can be replaced — would introduce genuine endogenous adverse selection, since a stale quote could then be picked off by a merely well-timed but otherwise uninformed counterparty. This is recorded in CLAUDE.md section 2.7 as the most valuable extension to the model, and is a natural candidate for the section 6.7 robustness checks. See also "no endogenous adverse selection at phi_informed = 0" above, which records the specific test-assertion consequence of this finding.

## 2026-08-12 Sharpe is mean over std of terminal PnL, not annualised
**Decision:** Throughout this project, "Sharpe" means `mean(terminal PnL across paths) / std(terminal PnL across paths, ddof=1)`, computed once per strategy over the Monte Carlo path set, with no annualisation factor applied.
**Alternatives considered:** An annualised Sharpe (e.g. multiplying by `sqrt(sessions per year)`), as is conventional for a time series of periodic returns.
**Reasoning:** Annualisation converts a per-period Sharpe into a comparable-across-frequencies statistic by assuming returns are a sequence of correlated draws along a single time series. That assumption does not hold here: each of the `n_paths` Monte Carlo paths is one independent, self-contained trading session (a fresh price path, a fresh RNG stream, inventory reset to `0`), not a sequential period of one ongoing strategy. The cross-path mean and standard deviation of terminal PnL are therefore already the right quantities — annualising would rescale by an assumption (a specific number of sessions per year) this project does not make and does not need, since paths are not chronologically ordered relative to each other.
**Consequence:** All Sharpe figures in `results/tables/headline_comparison.csv` and printed by `scripts/run_baseline.py` are this un-annualised, per-session definition. Any future comparison to externally reported (annualised) Sharpe ratios must account for this explicitly rather than reading the numbers as directly comparable.

## 2026-08-12 withdrawn-quote steps excluded from average spread and liquidation cost
**Decision:** In `run_episode`, a step where either side is withdrawn (quoted `NO_QUOTE_OFFSET` away from the mid, per the two "with limit" strategies) now records `StateRecord.spread_total` as `NaN` instead of the literal `ask - bid` (~`NO_QUOTE_OFFSET`). **Consequence:** Measured over 2000 paths after the fix: mean quoted spread (withdrawn steps excluded) is `1.3690` for `FixedSpreadWithInventoryLimit` and `1.3591` for `AvellanedaStoikovWithLimit` — both closely matching their unlimited counterparts' ~`1.359` average spread, with max included spread `1.37`/`1.38`, nowhere near `NO_QUOTE_OFFSET`. `withdrawn` steps are `3.005%` and `0.461%` of all steps respectively, matching the binding fractions already reported in the M5 headline run. `results/tables/headline_comparison.csv` and the printed section 5.3/6.2 breakdowns were not affected by this bug — they derive `spread_capture` from `fills["price"]` (actual executed prices) via `pnl_identity_components`, never from `spread_total` — so no previously reported number needs correction. Only `EpisodeResult.forced_liquidation_pnl`, which is computed but not yet surfaced anywhere in `scripts/run_baseline.py`'s output, was actually wrong, and is now fixed at the source.

## 2026-08-12 AvellanedaStoikov uses numpy.log1p for the microstructure term
**Decision:** `AvellanedaStoikov.quote` computes the microstructure term as `(2.0 / gamma) * np.log1p(gamma / kappa)` instead of `(2.0 / gamma) * math.log(1.0 + gamma / kappa)`.
**Alternatives considered:** Leaving `math.log(1.0 + x)`; using `math.log1p` instead of `numpy.log1p` (both are correct and available; `numpy.log1p` was used since the sweep instructions named it explicitly and `numpy` was already imported in this module for `RandomQuoter`).
**Reasoning:** For `x = gamma / kappa`, computing `1.0 + x` first and then taking the log loses precision when `x` is small, because the addition itself has already rounded `x` to the nearest representable double near `1.0` before the logarithm ever sees it. At `gamma = 0.0005` (the smallest value in the section 6.3 sweep) and `kappa = 1.5`, `x ≈ 0.000333`; the resulting absolute error in `log(1+x)` is then amplified by the `2/gamma = 4000` multiplier in front of it. `log1p(x)` avoids the intermediate addition entirely, computing the small-`x` expansion directly, so the error stays proportional to `x` rather than to the fixed-size rounding error of representing `1+x`.
**Consequence:** At the frozen default `gamma = 0.01` the difference between the two formulations is far below any tolerance used in this project (double-digit-nanometer-scale, not visible at the 1e-9 test tolerances), so no existing test needed updating — confirmed by the full suite still passing unchanged. The fix matters specifically at the low end of the section 6.3 gamma sweep, which is exactly where it is now used.

## 2026-08-12 no informed flow crossover exists within phi_informed in [0, 1]
**Decision:** `results/figures/informed_flow_crossover.png` and `results/tables/informed_flow_sweep.csv` report the measured result plainly: adverse selection never overtakes spread capture for any `phi_informed` in `[0, 1]`. At `phi_informed=1.0` (every arrival informed), adverse selection is `69.96%` of spread capture (spread capture `30.02`, adverse selection magnitude `21.01`) -- close, but the lines do not cross. No curve was fit and no crossover was extrapolated past `phi_informed=1.0`, which is the admissible range for a probability. **README walk-back candidate:** section 6.6's expectation of an in-range crossover was not met; state this plainly in the limitations section.
**Alternatives considered:** Extrapolating a fitted curve past `phi_informed=1.0` to claim a hypothetical crossover point (explicitly rejected by the task and by CLAUDE.md's honesty bar); silently reporting only the `phi_informed <= 0.40` portion of the range so the non-crossover isn't visible (rejected as burying a real null result, the same reasoning that applies throughout this file's other null-result entries).
**Reasoning:** The mechanism is structural, not a parameter-tuning accident. Every fill -- informed or not -- happens at the same posted price and the same size (`order_size`, fixed); the only thing `phi_informed` changes is what fraction of fills are, in expectation, on the side that turns out to be profitable to the counterparty. An informed arrival's edge over the next `informed_horizon` steps is bounded by the same mid-price move that determines whether it was "correct" -- it cannot extract more from a single trade than the spread offered on that trade, because the fill mechanism (section 2.6) does not let informed counterparties trade a larger size, trade more frequently, or negotiate a better price than an uninformed one. As `phi_informed -> 1`, almost every surviving fill is adverse (see the informed-flow gating mechanism entry above: wrong-direction informed arrivals are cancelled, not flipped), so adverse selection approaches spread capture in the limit but is mechanically bounded by it, not free to exceed it.
**Consequence:** The section 6.6 CV-bullet ("identifying the __% informed-flow threshold beyond which market making becomes unprofitable") cannot be honestly filled in as a threshold within `[0, 1]` -- the honest finding is that under this fill model, the business degrades continuously and severely (mean PnL falls from `60.37` at `phi_informed=0` to `9.23` at `phi_informed=1.0`, over an 84% drop) but does not cross into structural unprofitability from adverse selection alone within the admissible probability range. Introducing quote latency (see the "no endogenous adverse selection without quote latency" entry) is a plausible way a future extension could produce a genuine crossover, since it would let adverse selection scale with something other than the bounded per-trade edge this fill model imposes.

## 2026-08-13 Fill distances are measured from the mid, not the reservation price
**Decision:** In `run_episode`, the fill-intensity distances are `delta_b = S_i - bid` and `delta_a = ask - S_i`, both measured from the **mid** `S_i`, never from the reservation price `r_t`. The intensities are then `A * exp(-kappa * delta)` on each side independently.
**Alternatives considered:** Measuring from the reservation price (i.e. `r_t - bid` and `ask - r_t`), which is superficially attractive because the quotes are constructed symmetrically about `r_t` and so those distances are always equal to `spread_total / 2`.
**Reasoning:** Measuring from the reservation price would make both sides' fill probabilities identical by construction, which would destroy the entire mechanism being studied: the whole point of the AS skew is that shifting the quote centre away from the mid makes the inventory-reducing side *more* attractive to counterparties and the inventory-increasing side *less* attractive. That differential only exists if the counterparty evaluates the quote against the true market mid. Economically this is the correct model of a counterparty: they decide whether to trade based on how good your price is relative to the market, and they neither know nor care where your inventory sits or what reservation price you derived from it. CLAUDE.md section 2.6 states this explicitly; section 2.1's notation table originally described these symbols as distances "from the reservation price", which was inconsistent with 2.6 and has since been corrected in that file.
**Consequence:** This is the single load-bearing implementation detail that makes inventory skewing work at all. If it were changed to measure from `r_t`, every strategy in the project would collapse to the same fill process and the AS-versus-fixed-spread comparison would show no inventory control whatsoever; the bug would be silent, since the PnL identity would still reconcile perfectly. Worth guarding carefully in any refactor.

## 2026-08-13 Adverse-selection horizon is 20 steps, equal to informed_horizon
**Decision:** `simulation.adverse_selection_horizon = 20` steps, deliberately set equal to `flow.informed_horizon = 20`.
**Alternatives considered:** A shorter horizon (5-10 steps) to capture only the immediate post-fill move; a longer horizon (50+) to capture slower information; setting it independently of `informed_horizon`.
**Reasoning:** Two constraints pin this value. First, CLAUDE.md section 16 warns that if `informed_horizon` exceeds `adverse_selection_horizon`, the informed counterparty's edge materialises *outside* the attribution window and adverse selection can measure as positive — the attribution would then be systematically blind to exactly the effect it exists to measure. Setting them equal is the cleanest way to guarantee the informed move is fully inside the window. Second, at `dt = 0.005` and `T = 1.0` an episode is 200 steps, so a 20-step horizon is 10% of the session: long enough that the mid can move meaningfully relative to the ~1.36 spread, short enough that the attribution is not dominated by unrelated later drift. The reported residual term is the check on this choice — if the horizon were badly mis-set, the residual would dominate the decomposition, and measured it does not (residual `+0.0162` against spread capture `55.79` at the frozen defaults).
**Consequence:** The two horizons are conceptually distinct knobs (one governs the counterparty model, the other governs PnL attribution) that happen to share a value; they are stored and used separately so they can diverge, and `FillRecord.mid_after_horizon` follows the attribution horizon specifically. Any future change to `informed_horizon` should raise `adverse_selection_horizon` to match, or the section 16 failure mode returns.

## 2026-08-13 Terminal liquidation cost is half the average quoted spread per unit
**Decision:** Every episode reports two terminal PnL figures. Mark-to-market is `cash + q_T * S_T`. Forced liquidation is `cash + q_T * S_T - |q_T| * liquidation_cost`, where `liquidation_cost = liquidation_cost_multiplier * avg_spread` with `liquidation_cost_multiplier = 0.5` and `avg_spread` the episode's mean quoted spread (withdrawn-quote steps excluded).
**Alternatives considered:** Reporting only mark-to-market (the clean number that matches the theory); reporting only forced liquidation (the honest number); using a fixed per-unit cost independent of the strategy's own quoted spread.
**Reasoning:** Reporting only mark-to-market would flatter every strategy that ends holding inventory, because it books unrealised inventory at the mid as though it could be exited for free. Reporting only forced liquidation would break comparability with the AS closed form, which is derived under mark-to-market terminal wealth. Both are therefore reported. The half-spread multiplier is the natural choice: crossing the spread to exit a position costs approximately half the quoted spread per unit relative to the mid, so `0.5 * avg_spread` prices the exit at the same width the maker itself was quoting. Deriving it from the strategy's *own* average spread rather than a fixed constant keeps the penalty proportionate across strategies that quote at genuinely different widths (e.g. `RandomQuoter` versus AS under volatility stress).
**Consequence:** The gap between the two figures quantifies how much of a strategy's apparent PnL is unrealised inventory it would have to pay to exit, and is largest exactly for the strategies with the worst inventory control — which is the point. Note that this quantity depends on `avg_spread` being clean: the withdrawn-quote sentinel bug (logged above) corrupted precisely this number before it was fixed, producing a forced-liquidation PnL of `-707.25` against a mark-to-market of `+44.07`. `forced_liquidation_pnl` is computed on every episode but is not currently surfaced in any script's printed output or published table.
